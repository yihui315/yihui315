# Core Script Usage Manual

## Scope

This manual covers the four verified L1 read-only scripts included in the gstack audit package.

All examples are safe by default. They do not grant project readiness.

## Script Matrix

| Script | Purpose | Default output | Expected safe mode |
| --- | --- | --- | --- |
| `round-closeout-validator.ps1` | Checks whether the L1 round can close for documentation scope | console JSON or formatted output | read-only |
| `governance-artifact-hygiene.ps1` | Generates archive plans for governance artifacts | `Archive_Plan_YYYY-MM-DD.md` | dry-run |
| `human-evidence-intake-check.ps1` | Validates Human Operator evidence intake shape | `Evidence_Intake_Report_YYYY-MM-DD.md` | dry-run/read-only |
| `weekly-governance-health-check.ps1` | Runs closeout, artifact hygiene, and secret-shape checks together | `Weekly_Governance_Health_YYYY-MM-DD.md` | read-only |

## round-closeout-validator.ps1

```powershell
& .\Codex_L1_Governance\scripts\round-closeout-validator.ps1 -Json
```

Key fields:

- `closeout_status`
- `decision_json_parse_ok`
- `decision_summary.overall_decision`
- `decision_summary.execution_go`
- `env_like_files_present`

Blocked behavior:

- missing required L1 files
- invalid canonical decision JSON
- env-like files under the L1 root

## governance-artifact-hygiene.ps1

```powershell
& .\Codex_L1_Governance\scripts\governance-artifact-hygiene.ps1 -Json
```

Explicit target example:

```powershell
& .\Codex_L1_Governance\scripts\governance-artifact-hygiene.ps1 `
  -TargetDirectories @("artifacts", "screenshots", "logs", "mcp") `
  -OlderThanDays 90 `
  -DryRun:$true `
  -Json
```

Key fields:

- `status`
- `output_path`
- `candidate_items`
- `sensitive_shaped_path_hits`
- `blocked_targets`

Blocked behavior:

- target path outside L1 root
- sensitive-shaped paths such as `.env`, `secret`, `provider`, or `payment`

## human-evidence-intake-check.ps1

```powershell
& .\Codex_L1_Governance\scripts\human-evidence-intake-check.ps1 -Json
```

Explicit evidence file example:

```powershell
& .\Codex_L1_Governance\scripts\human-evidence-intake-check.ps1 `
  -EvidenceFile ".\Codex_L1_Governance\Projects\ai占卜.ai\当前状态\当前_Evidence_Gate_状态.md" `
  -Json
```

Key fields:

- `status`
- `missing_fields`
- `row_summary.total_rows`
- `row_summary.present_yes`
- `row_summary.present_no`
- `secret_shape_hits`

Blocked behavior:

- missing `submitted_by`, `submitted_at`, or `verified_environment`
- incomplete evidence rows
- invalid `present` values
- `present=yes` without evidence path
- secret-shaped content

## weekly-governance-health-check.ps1

```powershell
& .\Codex_L1_Governance\scripts\weekly-governance-health-check.ps1 -Json
```

Dry-run webhook notification example:

```powershell
& .\Codex_L1_Governance\scripts\weekly-governance-health-check.ps1 `
  -NotifyOn always `
  -NotificationProvider slack `
  -NotificationWebhookUrl "<slack-webhook-url-from-secret-store>" `
  -NotificationDryRun:$true `
  -Json
```

Real webhook notification example:

```powershell
& .\Codex_L1_Governance\scripts\weekly-governance-health-check.ps1 `
  -EnableNotification `
  -NotifyOn blocked `
  -NotificationProvider slack `
  -NotificationWebhookUrl $env:L1_SLACK_WEBHOOK_URL `
  -NotificationDryRun:$false `
  -Json
```

Key fields:

- `status`
- `score`
- `round_closeout.status`
- `artifact_hygiene.status`
- `secret_scan.secret_shape_hits`
- `secret_scan.env_like_files`
- `notification.status`
- `notification.provider`
- `notification.enabled`
- `notification.webhook_host`

Blocked behavior:

- closeout blocked
- artifact hygiene blocked
- secret-shaped hits
- env-like files present

## Webhook Notification Note

- webhook URL is provided at runtime only
- full webhook URL is not written to Markdown reports
- default `NotifyOn` is `blocked`
- default `NotificationDryRun` is `true`
- real sending requires both `-EnableNotification` and `-NotificationDryRun:$false`
- supported webhook types: Slack incoming webhook payload and generic JSON POST
- configuration example: `webhook_config_example.md`

## Compliance Boundary

- Scripts are read-only or dry-run by default.
- Scripts do not change gate decisions.
- Scripts do not prove project execution readiness.
- Scripts must not print, store, or commit raw secrets.
